## Rules for every fixer

1. Edit only the files your package owns. The one exception is a **shared edit** listed in your items: a
   minimal, additive change to one named function of another package's file. Make it last, with `Edit` on a
   freshly read file (never `Write`). Do not reformat, rename or move anything in that file.
2. Prefer a registry contribution from a file you own over a shared edit. Existing points include
   `command`, `notifications`, `token-menu`, `table-tool`, `table-panel`, `map-layer`, `sheet-section`,
   `sheet-tab`, `campaign-section`, `preparation-section`, `home-widget`, `settings` and `service` (see
   `registry.mjs` POINTS). Unknown fields are rejected, so do not invent new ones.
3. Search synonyms: put them in the command's `description`, never in a new field. P9 makes the palette
   match command descriptions (SV-02). Every HARD_TO_FIND fix registers at least one command whose label or
   description contains the words the audit searched for.
4. Tests: `node --test design/blueprint/tests/*.test.mjs` must pass at the end (baseline at triage time:
   2068 pass, 0 fail, about 5 s). Add new tests in new files
   named `tests/<package-id>-<topic>.test.mjs` or in test files you own. Do not edit the cross-cutting tests
   (`character-integration`, `ia-consolidation`, `increment10-review`, `review-fixes-*`, `w2*-integration`).
   If your intended change breaks one of their assertions, report it for the coordinator.
5. Verify in the running app (`http://127.0.0.1:8879/`). If it is down, start
   `python3 changes/interview-01/blueprint-checks/serve-nocache.py`. Use playwright-cli with your **own named
   session** (`d20-fix-<package-id>`) and uniquely named helper scripts. The audits showed that shared session
   names and a shared `pw` wrapper let one agent's clicks land in another agent's browser. Put evidence in
   `/Users/salvatoredicara/Workspace/Codex/d20-blueprint-evidence/2026-09-26/fix-<package-id>/`.
   Check desktop 1440x900 and phone 390x844 with touch, and both IT and EN, where the fix is visible.
6. The DEVELOPMENT.md contract still holds: every string goes through `ctx.t(it, en)`, dynamic HTML is
   escaped, there are no new dependencies and no census IDs in the UI. Code and comments are in English.
7. Never run git commit, reset, clean, checkout, stash or restore, and never create a worktree. The tree
   holds other people's uncommitted work.
8. Wrap anything that can run longer than about 2 minutes (background job plus a polled log).

## Cross-package contracts

- **One roll engine (P3).** `sheet-plus-domain.rollProfile` becomes the only way to build a roll. It covers
  conditions, exhaustion, riders and item modifiers. P2 favourites, the P5 action bar and the P3 dice tray all
  call it. P2 must not add a second roll path.
- **Personality fields (P1 → P2).** `actor.personality = {traits: [], ideals: [], bonds: [], flaws: []}`
  (arrays of strings). `PERSONALITY_SUGGESTIONS` is exported from `builder-plus-domain.mjs`. P2 renders the
  fields and shows no suggestions if the export is missing.
- **Sheet over the map (P2 → P6).** `characters.mjs` exports `openSheetOverlay(ctx, actorId, tab)`.
- **Active effects (P5 → P6).** `combat-ui.mjs` exports `renderActiveEffects(ctx, actorId)`, and the Table
  inspector calls it.
- **Table initiative (P5 → P1).** `combat-tracker.mjs` exports the Table initiative dialog, and
  `app.mjs startEncounter` calls it.
- **Enemy visibility policy (P10 → P6, P3).** `campaign-settings-domain` exposes one «Cosa vedono i
  giocatori» policy getter. Token badges (TV-25), hit probability (TV-76) and names read it.
- **Content filter (P10 → P3, P4).** `safety-domain.filterFor(state, role)` wraps chat and handout rendering.
- **Seed data.** Sample actors live in `state.mjs` (P1) and sample items and spells in `srd-sample.mjs` (P2).
  Other packages add fields only as a listed shared edit and never change existing seed values.
