# Market census — lighter and newer VTTs (Owlbear ecosystem, Alchemy, Shard, Quest Portal and others)

Access date: **2026-09-23**. Author session: market-census subagent (interview-01). This file
is a capability-level census for one cluster. It extends, and does not replace,
[REFERENCE_COVERAGE](../../../docs/interview/REFERENCE_COVERAGE.md) (broader-comparison rows for
Owlbear, Shard, Alchemy, Quest Portal and extension ecosystems) and the Owlbear/Alchemy/Shard
entries already kept in [RESEARCH](../../../docs/interview/RESEARCH.md) (for example R075, R079,
R080, R106, R128, R130, R143, R161–R168, R177). Those older rows keep their own dates and limits.

## Scope, versions and access limits

- **Products.** Owlbear Rodeo 2 core and its extension catalogue; Alchemy RPG; Shard Tabletop;
  Quest Portal; Let's Role; AboveVTT (D&D Beyond overlay); Beyond20; Improved Initiative;
  TaleSpire; Tabletop Simulator (as used for D&D); Tableplop; The Forge (Foundry hosting).
- **Layers.** Each row names the layer: *core*, *official extension* (Owlbear marks these
  "built by Owlbear"), or *third-party extension/module* with its author. A third-party
  capability is never attributed to the host product.
- **Owlbear core docs were not readable today.** `docs.owlbear.rodeo` answered every direct
  request with a Cloudflare bot challenge. It was **not** bypassed. Owlbear core rows therefore
  rely on the official blog release notes (2.0 Beta Patch 8, 2.0 Launch Patch, 2.2, 2.3, 2.4,
  Map Alignment post), the official SDK release notes on GitHub, search-engine snippets of the
  docs pages (marked *official docs, search snippet*), and earlier readings kept in RESEARCH.
- **Owlbear extension listings.** The catalogue is the official repository
  `github.com/owlbear-rodeo/extensions` (`extensions.json`, last push 2026-08-26, 102 entries).
  Each entry points to the author's `store.md`, which is the text shown at
  `https://extensions.owlbear.rodeo/<id>`. All 101 reachable listings were read on 2026-09-23
  (the `trackers` listing returned HTTP 403). Listings carry no version; they are the author's
  own claims (*store page*). Only D&D-relevant extensions are tabled; system-specific ones for
  other games (Daggerheart, Shadowdark, Dragonbane, Draw Steel, Lancer, Fabula Ultima and similar)
  were skipped except where a pattern transfers.
- **Other evidence kinds.** *Official docs* = the product's help centre or knowledge base.
  *Release notes* = dated changelogs or patch notes. *Official source code* = settings and
  command definitions read in the product's public repository (Improved Initiative, Beyond20);
  it proves an option exists, not how it is presented. *Observed (public page)* = what a public
  landing page visibly shows. *Community* = blog or forum opinion, used only as a demand signal.
- **Method limits.** Pages were read through curl/HTML stripping or a web-fetch summariser.
  No account, installation, runtime session or human playtest took place. Tableplop's Notion
  documentation did not render for a fetcher, so its rows are thin and labelled. Alchemy help
  articles and Shard "howto" articles expose no product version; Shard howto dates show no year.
- **Coverage column.** Same legend as the sibling census files. **F-0nn** = the family exists in
  [FEATURES](../../../docs/interview/FEATURES.md) and the pattern is at least named there or in a
  flow/page document. **PARTIAL F-0nn** (or PARTIAL GAP-nn) = the family or gap exists but a
  keyword check of `docs/interview/` did not find this sub-pattern. **NEW** = no family or anchor
  found. GAP-nn refers to REFERENCE_COVERAGE. The check is a grep, not a re-read of every page:
  PARTIAL and NEW are work items to verify, not proven absences.
- **Standing exclusions kept.** In-app voice/video (F-017) and in-app music (F-030: music is
  external for now) stay out of scope; their rows are kept for interface lessons only. 3D
  environments are excluded; 2D elevation is not. AI assistance (GAP-18) and external
  integrations (GAP-17) are recorded as capabilities, never as authorised spending, data
  transfer or accounts.
- **Rules content.** No rules text is reproduced. Where an extension's behaviour conflicts with
  2024 rules (for example temporary hit points), the row says so; the census does not adopt it.

## Pattern notes

The 18 patterns below are the ones most worth copying. Each says why it works and which product
does it best. Conflicts follow.

1. **A small, fixed set of command surfaces (Owlbear SDK, VTL-231/232).** Everything is an
   action button, a toolbar tool with modes, a context-menu item (with an embedded mini-panel),
   a popover, a modal or a toast. Users learn where things live once. More than a hundred
   extensions still feel like one product. *Best: Owlbear.* d20 Studio should define the same
   grammar for Tavolo before adding features.
2. **Object commands in the context menu, with a touch equivalent (VTL-232, VTL-126).**
   Right-click on desktop, long-press or tap-then-"…" on touch. Stat Bubbles and GMG put an
   editable panel inside the context menu, so HP and AC change without opening a sheet.
   *Best: Owlbear + Stat Bubbles.*
3. **Arithmetic in number fields (VTL-234).** Type +6, -8 or =15 in an HP field. Arrow keys and
   the scroll wheel step values. This is faster than dialogs and becomes muscle memory. *Best:
   Owl Trackers (explicit "=" for set, per-field opt-out), Battle Board (chains).*
4. **One control for roll audience (VTL-173, VTL-113, VTL-172).** Everyone / Self / GM & Self /
   GM only, placed next to the dice and remembered. Bones! adds a useful twist: a hidden roll
   still tells the table that a roll happened. *Best: Dice+.* This fits I-031/I-033 secret rolls.
5. **Roll cards that carry the next action (VTL-152, VTL-153, VTL-164).** An attack card offers
   Advantage, Critical and Damage. A damage total applies full or half to the selected creatures.
   A save DC rolls saves for the whole group. Single dice can be rerolled or the card deleted.
   *Best: Shard.* AboveVTT adds ×¼ damage and "add everyone in the AoE".
6. **Player view as a first-class, configurable surface (VTL-128, VTL-119, VTL-124, VTL-127).**
   Monster HP shown as exact, label, colour, damage taken, or hidden. Players may *suggest*
   damage or tags and the DM accepts (VTL-129). *Best: Improved Initiative.* Word labels
   (Healthy/Bloodied/Down) pair with colour for accessibility.
7. **Every tracker command has a rebindable hotkey and chooses its own placement (VTL-130).**
   n next turn, t damage, l heal, h hide, r reaction. Each command may appear in the row, in the
   action bar, or in neither. *Best: Improved Initiative.* This supports keyboard-first DMs
   without cluttering touch layouts.
8. **Reset vs Clear, and a finish-encounter wizard (VTL-117, VTL-155).** "Reset" reruns the same
   fight; "Clear" empties it. "Finish encounter" hands out treasure and XP, writes the log and
   removes leftovers in one confirmed step. *Best: Shard (finish), Clash (reset/clear).*
9. **Effects with duration that end on start or end of a turn, with a table-wide alert
   (VTL-118).** *Best: Clash.* Ours must follow each ability's own timing (CLAUDE.md rule).
10. **Preview before push, and hide the whole UI (VTL-161, VTL-067, VTL-191).** The GM
    previews a scene or fog as players will see it, then pushes it live. A single shortcut
    clears the UI for the shared screen. *Best: Alchemy (scene preview), Owlbear (fog preview,
    hide UI).*
11. **Per-player visibility, not just hidden/visible (VTL-143, VTL-142, VTL-187).** A token
    visible only to chosen players. Vision per owner. Explored-area memory with a reset. *Best:
    Smoke & Spectre.* TTS's per-seat hidden zones show the same idea in a non-grid context.
12. **Guided map alignment with a magnifier that moves off the finger (VTL-063).** Three steps:
    offset, cell size, refine. The next button follows the cursor. *Best: Owlbear (2026-05).*
13. **Handouts and entries that flow into chat and journal (VTL-158, VTL-053, VTL-052).**
    Shared handouts post to chat and can be saved to the journal. Any rules entry can be shared
    to chat as a link. Documents can be shown to everyone for a moment or shared read/write per
    player. *Best: Shard (chat → journal), Let's Role (per-player rights + show to all).*
14. **Loot and shops attached to things in the world (VTL-095, VTL-096, VTL-097).** The chest
    or merchant token holds items and coins. Players take items to the party or a member. A cart
    shows the net total. The GM may edit the sale price (haggling) and closes the shop. *Best:
    Game Master's Grimoire.* Shard's "shop from a book list" is the low-prep version.
15. **Session safety that asks nothing mid-scene (VTL-058, VTL-059, VTL-169).** Lines and veils
    live in the profile and apply to every game. Table topics are shown again before each
    session. An anonymous X-card or Stop can be sent in one action; Rumble adds "raise hand".
    *Best: Alchemy (profile-level), Let's Role (pre-session reminder, not logged).* This fills
    GAP-16 without turning F-032 into a questionnaire.
16. **Auto-drafted session log (VTL-054, VTL-155).** When the last person leaves, the product
    writes attendance, duration, scenes used and key events into a note. The GM can switch it
    off or keep it private. *Best: Quest Portal.* It feeds F-029 without extra work for the DM.
17. **Reuse at the right level (VTL-079, VTL-081, VTL-082, VTL-083).** Universe or in-game
    content (Alchemy). Prefabs that are themselves editable scenes (Owlbear). Token templates
    that persist across scenes (Persistent Tokens). A token named "Goblin" loads the saved
    goblin block (Clash). *Best: Owlbear Prefabs for groups, Clash auto-load for creatures.*
18. **List ↔ map locate (VTL-235, VTL-183).** Double-click a row to find the token. Selecting a
    token highlights its row. Shift+click also recentres players, so shared recentring is always
    opt-in. *Best: Pulpscape (opt-in sync).* This respects F-051's refusal of forced recentring.

### Conflicts and cautions between products

- **Automation depth vs minimal core.** Owlbear keeps rules out of core and relies on
  extensions (VTL-231, VTL-244). Shard, AboveVTT and Beyond20 automate rolls and damage. d20
  Studio already chose rules automation with DM discretion. Owlbear's lesson is about *surface
  discipline*, not about leaving rules out.
- **Temporary HP.** GMG raises max HP when temp HP is added (VTL-125). Other trackers keep a
  separate temp-HP bubble (VTL-126). Follow the 2024 rules; do not copy GMG.
- **Recentring.** Clash and GMG move the GM's camera to the active token by default. Pulpscape
  makes shared recentring an explicit Shift+click. F-051 already refuses forced recentring, so
  auto-follow must be a personal opt-in (Clash's player toggle).
- **Roll privacy semantics.** Bones! announces that a hidden roll happened. Rumble "Self" rolls
  and Dice+ "GM only" do not. Our I-031/I-033 decisions govern; pick one default and show it
  in the roll control.
- **Where chat lives.** Rumble keeps chat only in the browser and relies on Discord for
  persistence (VTL-169, VTL-225). Alchemy and Shard keep a server-side journal/chat. A
  persisted log is required for our logged consequences.
- **Turn models.** Checkbox/any-order initiative (VTL-115), side initiative and minion groups
  (VTL-121, VTL-131) differ from the 2024 baseline. They stay in GAP-07 as options for later
  review; they must not change defaults.
- **Imports from D&D Beyond.** Shard dropped its DDB import in 2024 because upkeep was
  impractical (VTL-200). AboveVTT and Beyond20 live on top of DDB pages and ship fixes almost
  daily (AboveVTT beta 1.60-beta21 on 2026-09-23). F-028 should prefer documented formats and
  treat DDB scraping as fragile.
- **AI features.** Quest Portal's assistant uses paid credits, uploads user PDFs and asks users
  to check results (VTL-196, VTL-217). Clash hands users a prompt for an external chatbot
  (VTL-083). Both are recorded under GAP-18 only. Neither is authorised spending or data
  transfer.
- **Real-time timers vs the fiction clock.** Ticker and /timer are real-time countdowns
  (VTL-178). OwlClock/Calendar! track fiction time (VTL-056). F-010 already rejects a mandatory
  real timer for rests. A GM countdown for puzzles or breaks would be a separate, optional
  capability.
